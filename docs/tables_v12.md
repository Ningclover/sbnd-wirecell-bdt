# What the table builder saves (spec v1.2)

Generated by `tables/list_columns.py` from the full Aurora build of sample `aurora-r2-nuecc` (61,248 files, 2026-11-19); every count below is read from the files. Table names carry `_<sample>` and the build tag.

The builder (`tables/build_tables.py`) reads the merged CAF files and writes, per sample: a file table, a candidate table, a truth table, and with `--objs` one object table per level-1 small model. A summary `build_<sample>.json` records files, errors, timeouts, candidates and object rows per model.


## `files_<sample>.parquet`: one row per input file (written even when the file failed or has no candidate)

61248 rows x 16 columns in the example build.

| family | columns | what it holds |
|---|---:|---|
| key | 1 | Which sample, file, run, subrun, event; which candidate (`cand`) or object (`index`) or true neutrino (`nu_idx`) within it. |
| file bookkeeping | 12 | Per input file: path, event and candidate counts, exposure (POT, spills, gates, generated events), simulation or data, the error text when the file failed. |
| label and match | 1 | Truth-to-candidate match: what the candidate's true partner is (neutrino, cosmic, missing), that neutrino's properties (`m_*`), vertex distances, the signal label, the background class, the train/test split. |
| candidate basics | 1 | Software version of the file; the electron energy used by the e500 selection; the reconstructed vertex; whether the space-charge fallback was used; the placeholder flag of a neutrino without a usable candidate. |
| true neutrino | 1 | What the simulated neutrino was (type, charged- or neutral-current, mode, energy, deposited energy), where it interacted (raw and space-charge-shifted vertex), its outgoing lepton. |

## Special cases the builder records

- A file that cannot be opened or read: `error` in the file table starts with `OPEN_FAIL` or `READ_FAIL`; the file contributes nothing; counted in the summary.
- A file over the time limit (`--timeout`, default 900 s): `error` is `TIMEOUT after ...`; same treatment; `timeouts` in the summary.
- Truth-match tree unreadable: candidates are written without label columns, `label_unreadable = 1` on the file and its rows.
- True particle list unreadable: only `true_lep_pdg` / `true_lep_ke_mev` are lost, `truth_pf_unreadable = 1`.
- Candidate whose true partner is not found: `partner_kind = missing`, counted in `partner_missing`.
- No space-charge-shifted true vertex: `dist_sce_cm` falls back to the raw distance, `sce_fallback = 1`.
- Data files: no truth tree, so the truth table is empty, label columns absent, `ismc = 0`.
- Object lists of unequal length inside one model, or a missing flag branch: the missing entries are NaN. A model whose branches are absent from a file gets no rows from that file.
- Objects are stored for every candidate, also where the shipped software did not run the model (its `pre_cut` in `l1_models.py`); training applies the pre-cut itself. `pio_2` rows come in pairs, one per photon of each pair, as the shipped software fills them.
